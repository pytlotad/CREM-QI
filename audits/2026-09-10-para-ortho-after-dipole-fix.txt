

307. PRZEGLAD README POD KATEM ZGODNOSCI Z FIZYKA I Z KODEM: GLOWNA LICZBA
     SEKCJI STATUSU NIE ODTWARZA SIE NA DOMYSLNYM KODZIE OD 2026-09-26
     (dane: audits/data/section-307/)

     Polecenie autora: zweryfikowac README pod katem czegos pilnego do
     sprawdzenia ze wzgledu na zgodnosc z fizyka.

307a. NAJPILNIEJSZE: 199,43 ps PRZY n = 1 NIE JEST DZIS ZACHOWANIEM
     DOMYSLNYM.  Sekcja statusu i "Czas kolapsu ustawia promien startowy"
     podaja dla konfiguracji "kwant, n = 1, bez podlogi" mediane
     199,430 ps (20 ukonczonych trajektorii, ziarno nadrzedne 42, wszystkie
     koncza na progu retardacyjnym) jako zachowanie "domyslne dzis", wraz z
     plaskoscia wzgledem kroku sekularnego (0,4 procent) i wynikiem para/orto
     1,000127 (24/24) ze znakiem zgodnym z rzeczywistoscia.  Narzedzie, ktore
     te liczby dalo (tools/para_ortho_lifetimes.cpp), uruchomione na HEAD:

       konfiguracja                                ukonczone pary   t_para
       domyslna                                    0/4 (600 s)        --
       A: CREM_LS_FREE_MAGNITUDE=1                 0/2 (300 s)        --
       B: A + oba wyjscia z 288                    0/2 (300 s)        --
       C: B + CREM_NO_SPIN_MAGNITUDE=1             2/2           198,98 ps
       D: tylko CREM_NO_SPIN_MAGNITUDE=1           2/2           198,99 ps

     Wedlug README taka trajektoria to 63 checkpointy, czyli okolo minuty;
     zadna nie konczy sie w 600 s.  Zmiany z tej sesji (288, 305) NIE sa
     przyczyna -- ich wyjscia awaryjne nie przywracaja wyniku.  Przywraca go
     wylacznie CREM_NO_SPIN_MAGNITUDE=1, czyli cofniecie commitu 5ca1bba
     (2026-09-26, "Make the photon spin magnitude the default"), ktory
     wprowadzil foton niosacy hbar i odmowy ceiling -- czyli dokladnie
     zamkniecie kanalu E1 przy J_phi + n <= 1 z 296b/298a i pelzanie z 299.
     Liczba 199,44 ps pochodzi z b93c1e5 (2026-09-11), sprzed tej zmiany;
     od tamtej pory crem_collapse.hpp zmienil sie w 37 commitach, z czego
     reszta przesuwa wynik o ~0,2 procent (198,98 wobec 199,43 ps).
     README twierdzi wiec o zachowaniu domyslnym cos, czego domyslny kod nie
     robi: przy obecnym domyslnym czasu kolapsu przy n = 1 nie da sie
     zmierzyc w ogole (299a).

307b. PILNE I SPOWODOWANE PRZEZE MNIE: 305 PRAWDOPODOBNIE USUWA MECHANIZM,
     KTOREMU README PRZYPISUJE ZNAK PARA/ORTO.  Sekcja "Domkniecie wymiany
     L <-> S" wiaze wynik 1,000127 (24/24) z tym, ze orbitalne L orto narasta
     miedzy fotonami przez transport spin-orbita (+2,196e-04 hbar na
     checkpoint, 33/33 dodatnich), a para nie.  Transport typu L.S z 305
     z definicji zeruje zmiane |L| w transporcie.  Zapowiedz z dwoch par:
     C (stary transport) 1,00019, D (nowy) 0,99999 -- kierunek zgodny z
     obawa, ale dwie pary niczego nie rozstrzygaja.  README zapisuje tez,
     ze wczesniej ODRZUCONO zaciskanie |L| do wartosci kolowej, bo dzialalo
     jak zapadka, zalezalo od kroku sekularnego (216,69 / 210,92 / 204,90
     ps) i przesuwalo pierwszy foton o 6,5 procent.  Wariant (b) to inna
     operacja (zachowuje |L| w obie strony, nie zaciska do granicy), a
     pierwszy foton przesunal sie w 304 o 0,0075 procent -- ale zaleznosci
     od kroku NIE sprawdzilem.  Promocja z 305 zostala zrobiona bez
     znajomosci tych dwoch zapisow i jest do ponownej oceny.

307c. MNIEJ PILNE: "ZMIERZONE 124,49 ps" TO WIODACY RZAD QED.
     2 hbar/(alpha^5 m c^2) = 124,4942 ps.  Pomiar (Al-Ramadhan i Gidley
     1994, ktorych kod sam cytuje w statistics_archive.hpp z poprawna
     wartoscia 7990,9 us^-1) daje 125,14 ps, a QED z poprawkami 125,16 ps.
     README (sekcja statusu, tabela przy "Czas kolapsu...") i komentarze w
     configuration_panel.hpp:136 i crem_collapse.hpp:223 nazywaja 124,49
     ps "zmierzonym".  Porownanie "1/3 wobec 1/2" jest przy tym poprawne,
     bo dotyczy wlasnie wiodacego rzedu -- bledna jest tylko etykieta, o
     0,52 procent.
     Przy okazji sprostowanie do 285: tam liczylem tau_2gamma jako
     4 r*/(alpha^5 c), a r* = mu_e/(e c) zawiera g/2 = 1,00116, wiec
     dostalem 124,64 zamiast 124,49 ps.  0,12 procent nie rusza wniosku o
     siedmiu rzedach.  Kod produkcyjny tego bledu nie ma
     (maxwell_validation.hpp uzywa hbar/(m c)).
